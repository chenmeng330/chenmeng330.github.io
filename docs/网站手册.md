# 网站手册

写给以后要自己动这个站的你。看完这一份，加文章、改样式、传到 GitHub 都不用再问人。

---

## 一、这个站是怎么跑起来的

三样东西。

**内容是 Markdown。** `src/content/texts/` 下面每篇文章就是一个 `.md` 文件，开头一小段用 `---` 包起来的字段（叫 frontmatter）说明标题、网址、分类，下面就是正文。你写的东西只存在这里。

**外壳是 Astro。** `src/pages/` 里的几个 `.astro` 文件负责"把文章摆成网页"。首页把最新几篇排出来，`fiction/index.astro` 把作品按类目分组，`[...slug].astro` 负责单篇详情。`src/styles/global.css` 是全部样式。

**产物是静态 HTML。** 构建的时候 Astro 把你的 Markdown 和外壳拼在一起，生成一堆 `.html` 文件放进 `dist/`。没有数据库，没有后端，服务器只需要会发文件。

所以流程是：改 Markdown → 构建 → 得到 HTML → 传到 GitHub Pages。GitHub 那边会自动帮你跑构建（`.github/workflows/deploy.yml`），你只管把改动推上去。

## 三、加一篇文章

### 1. 新建文件

在哪一类就放哪个文件夹。比如写一篇新短篇，就建 `src/content/texts/fiction/wode-xinpian.md`。

文件名本身不影响网址，但建议用拼音，好认。

### 2. 写开头那几行

```markdown
---
title: "我的新篇"
slug: "wode-xinpian"
kind: fiction
category: "原创短篇"
date: 2026-12-01
summary: "一句话摘要，会显示在列表里。"
draft: false
---

正文从这开始。

第二段要空一行再写。
```

字段逐个说。

- `title` 标题，中文随便写
- `slug` 网址，`wode-xinpian` 就是 `https://你的域名/wode-xinpian/`，只能用英文数字和连字符，改了这个旧链接就死了
- `kind` 三选一，`fiction` 作品、`longform` 长文、`essay` 随笔
- `category` 栏目里再分的小类，比如"原创短篇""东方同人""考据"，同一个名字会自动归到一起
- `date` 写成 `2026-12-01`，列表按它倒序
- `summary` 可以不写，不写列表里就只显示标题
- `order` 可选，写了数字就用它排序，越小越前，适合想把某篇钉在顶上
- `draft` 写 `true` 就暂时不发布，本地也看不到

### 3. 正文写法

就是普通 Markdown。

```markdown
# 这是大标题（一般不用，页面标题已经是 h1 了）
## 这是小节标题
### 再小一级

正文段落之间必须空一行，不然会粘成一段。

*斜体*、**加粗**、`行内代码`。

> 引用。

---

上面那三个减号会变成一条装饰性分隔线。
```

### 4. 加图

图片放在 `public/images/` 下面，比如 `public/images/wode-xinpian/01.jpg`。

正文里这么写：

```markdown
<figure>
  <img src="/images/wode-xinpian/01.jpg" alt="图片说明" loading="lazy" />
  <figcaption>图注写这里</figcaption>
</figure>
```

`alt` 是图片加载不出来时显示的字，也读屏软件会念，随手写一句。

`src` 开头那个 `/` 代表网站根目录，不要写成 `public/images/...`，那样会 404。

### 5. 看效果

改完存盘，本地预览会自动刷新（怎么开下面讲）。确认没问题再上传。

## 四、本地预览

**前提是 Node 已经装好。** 现在这台机器上 Node 藏在一个奇怪的地方，没进 PATH，所以要用完整路径。你以后自己装了 Node（去 nodejs.org 下 LTS 版就行），命令会简单很多。

### 现在的做法

打开 PowerShell，粘这一坨。

```powershell
$env:PATH = "C:\Users\Qxiz\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin;" + $env:PATH
$env:ASTRO_TELEMETRY_DISABLED = "1"
$env:XDG_CONFIG_HOME = "C:\Workarea\.config"
cd C:\Workarea\qinxi-site
node node_modules/astro/bin/astro.mjs dev --port 4321
```

然后浏览器开 <http://127.0.0.1:4321/>。改文件自动刷新，`Ctrl+C` 停。

那两个环境变量不是装饰。`ASTRO_TELEMETRY_DISABLED` 不让 Astro 往用户目录写统计文件，`XDG_CONFIG_HOME` 给它找个能写的地方，少了会报 EPERM。

### 以后自己装了 Node

```powershell
cd C:\Workarea\qinxi-site
pnpm install     # 第一次，或者依赖变了才跑
pnpm dev
```

### 生成正式文件

```powershell
node node_modules/astro/bin/astro.mjs build
```

产物在 `dist/`。想本地看构建结果可以 `node node_modules/astro/bin/astro.mjs preview`。

## 五、改样式、改文字

**想换配色、字号、行距**，全在 `src/styles/global.css` 开头的这几个变量。

```css
:root {
  --paper: #f6f1e7;    /* 纸色 */
  --ink: #1b1814;      /* 墨色 */
  --accent: #8e3527;   /* 朱红 */
}
```

改完刷新就变。别的地方引用的是变量，会一起变。

**想改导航**，`src/layouts/Base.astro` 里那个 `nav` 数组，加一项减一项都行。

**想改页脚那句话**，同一个文件最底下。

**想改首页自我介绍**，`src/pages/index.astro`，找那段中文直接改。

**想改"关于"页**，`src/pages/about.astro`。

## 六、挂到 GitHub

### 先装 Git

这台机器现在没有 Git。两种装法。

**命令行版**，装完能在 PowerShell 里用 `git`。

```powershell
winget install --id Git.Git -e --source winget
```

装完关掉 PowerShell 重开，`git --version` 有输出就成。

**图形版 GitHub Desktop**，自带 Git，不用配 PATH，点按钮就行。适合不想背命令的人，去 <https://desktop.github.com/> 下。

两个都装也不冲突。

### 第一次把项目变成仓库

在 `C:\Workarea\qinxi-site` 里执行。

```powershell
cd C:\Workarea\qinxi-site
git init
git add .
git commit -m "第一次提交"
```

`git init` 是给这个文件夹装上版本管理的脑袋。`git add .` 是把改动放进待提交区。`git commit` 是拍一张存档照。

`.gitignore` 已经把 `node_modules/` 和 `dist/` 排除了，这俩一个几百兆一个随时能重建，不该进仓库。

### 在 GitHub 上建仓库

1. 登 github.com，右上角 `+` → New repository
2. 名字建议直接填 `<你的用户名>.github.io`。这样网站地址就是 `https://<你的用户名>.github.io/`，路径最短，图片和链接都不会出错
3. 选 **Public**（Private 仓库用不了免费的 Pages）
4. 下面的 Initialize 选项一个都别勾，你已经本地有文件了

建完页面会给你一段命令，大概是这样的。

```powershell
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

`remote add` 是告诉本地这个仓库在网上的哪。`push` 是上传。

第一次 push 会弹窗让你登录 GitHub，走浏览器授权就行。

### 让 GitHub 自动构建

推上去之后。

1. 打开仓库页面，Settings → 左边找 Pages
2. Source 那一栏选 **GitHub Actions**
3. 回到 Actions 标签页，能看到一个叫"部署到 GitHub Pages"的任务在跑
4. 跑完（大概一两分钟）再去 Pages 页面，会显示你的网址

以后每次 `git push`，它都会自动重新构建发布。你本地不用构建。

### 如果仓库名不是 `<用户名>.github.io`

那网址会变成 `https://<用户名>.github.io/<仓库名>/`，所有以 `/` 开头的路径都会指错地方。这时候要改两个文件。

`astro.config.mjs`：

```js
export default defineConfig({
  site: "https://<用户名>.github.io",
  base: "/<仓库名>",
  // ...
});
```

还有正文里那些 `<img src="/images/...">`，以及 `rss.xml.ts` 里的链接。麻烦，所以能叫 `<用户名>.github.io` 就叫这个。

### 改动之后怎么传

```powershell
cd C:\Workarea\qinxi-site
git add .
git commit -m "加了新短篇"
git push
```

三步。`git status` 随时能看现在有哪些改动还没提交。

## 七、几条 Git 常识

- **commit 是本地存档，push 才是上传。** 忘了 push，GitHub 上什么都没有。
- **commit 信息写人话。** "改了标题"比 "update" 有用得多，半年后你会感谢自己。
- **推不上去先 `git pull`。** 多设备改同一个仓库会打架，拉一下再推。
- **搞砸了能回来。** `git log` 看历史，`git reset --hard <那串哈希>` 回到某个存档。仓库里只有文字，重来成本很低。
- **不要 `git add` 那些几十兆的东西。** 视频、原始 psd 放网盘，站点只放压缩过的图。

## 八、常踩的坑

**段落粘成一大坨。** Markdown 里两段之间必须空一行，只有换行不算分段。

**首行缩进变成代码块。** 行首四个空格或一个 Tab 在 Markdown 里是代码的意思。中文习惯的行首缩进在这个站里不要用，CSS 会自己处理缩进。

**全角空格。** 复制粘贴进来的 `　　` 会跑到正文里显示成怪空隙，粘完扫一眼。

**标题带序号。** 从 txt 导入的文章有时标题前面挂着"3"或者"一、"，顺手删掉。

**图片 404。** 路径以 `/images/` 开头，不是 `public/images/`，也不是 `../images/`。

**日期写成 `2026-12-1`。** 要补零，`2026-12-01`。

**改完没生效。** 本地看是不是 dev server 还开着，线上看是不是 Actions 还没跑完，或者 push 根本没成功。
